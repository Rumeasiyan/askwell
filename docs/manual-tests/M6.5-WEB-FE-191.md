# Manual test — M6.5-WEB-FE-191, mixed answers: each claim points at its own kind of source

**Ticket:** `M6.5-WEB-FE-191` — when an abstained or partial answer is escalated to the web, the
escalation's own answer renders in its own region with claim-level attribution: document claims
keep their leader and margin card, web claims point into the web region, hover/keyboard pairing
never crosses between the two, and a web result that agrees with a document never joins the
margin.

**Version under test:** `0.6.16`
**Time:** about 30 minutes.

**What is being checked.** `web/components/ask/ask-screen.tsx` (`WebAnswerBlock`, `ClaimSpan`'s
`documentRaised || webRaised` OR, `AnswerProse`'s `ordinalOffset`), `web/components/ask/web-pairing.tsx`
(`useLiveWebPairs`, `useWebRaised`), `web/lib/web-citations.ts` (`applyWebCitation`), and
`web/lib/web-search.ts` (`escalateWebSearch`) — wired end to end against the real backend
(`askwell.websearch.ask_escalate_web`, `M6.5-WEB-BE-188`/`-189`).

**Unlike `M6.5-WEB-FE-190`, this ticket is reachable through the running app.** `M6.5-WEB-FE-186`
already wired the escalation offer onto the abstention and partial-answer surfaces, and this
ticket is what turns a click on "Search the web" into a rendered answer. No scratch page is
needed — Part 2 below is a real cold-start walkthrough.

**Depends on live web access.** `escalateWebSearch` sends the question to `ddgs` for real
(C10 — this is a deliberate, per-question egress grant, not a violation of C1). If the machine
running this test has no internet reachable, steps 6 onward will show the "could not reach the
web" state instead of an answer — read "Known gaps" before treating that as a defect.

## Before you start

```
cd ~/external/quantum-plus/askwell
```

If you have never run Askwell before:

```
cp -n .env.example .env
```

Open `.env`, find `POSTGRES_APP_PASSWORD`, `SANDBOX_POSTGRES_PASSWORD`, `SANDBOX_OWNER_PASSWORD`
and `SANDBOX_READONLY_PASSWORD`, and put any word after each `=` if it is blank.

You will need one short text document whose content you control, so the "documented half"
of a mixed answer is predictable. Create it now:

```
mkdir -p /tmp/askwell-fe191
cat > /tmp/askwell-fe191/notice-policy.txt <<'EOF'
Company Notice Policy

Employees must give thirty (30) days written notice before resigning
from their position. Notice periods for probationary staff are seven (7)
days.
EOF
```

## Part 2 — cold start, produce a mixed answer

### 1. Bring the stack up

```
podman compose up -d
```

### 2. Open the app

```
http://127.0.0.1:8000
```

**You should see:** first-run, if this is a fresh install (or the ordinary Ask screen otherwise).

### 3. Add the notice-policy document

Complete first-run (or use the ordinary add-source flow) pointing at
`/tmp/askwell-fe191/notice-policy.txt`. Wait until the library shows it as indexed —
`docs/manual-tests` convention: refresh the library page and confirm the source is marked
askable before moving on.

### 4. Ask a two-part question, one half your document covers, one it does not

In the composer on the Ask screen, type and send:

```
What does company policy say about the notice period for a resigning employee, and what is the current statutory minimum notice period?
```

**You should see:** the question appear as the live turn, retrieval/streaming steps run, and an
answer arrive. Because nothing in your one-document corpus discusses a statutory minimum, this
should land as a **partial answer**: the answered part cites `notice-policy.txt` (30 days) in the
margin, and a "Not covered by your files" block names the statutory-minimum half explicitly. If
instead it abstains entirely, that is also an acceptable starting point for this walkthrough —
either state offers the escalation below it (this ticket doesn't change which of the two
`ask.md` states is chosen, only what happens after).

### 5. Confirm the margin, at this point, is unchanged from before this ticket

Look at the provenance margin (right-hand column, or inline beneath the answer if your window is
narrow). **You should see:** exactly one card, for `notice-policy.txt`, with its leader line
pointing at the "30 days" sentence, and no dashed "From the web" region anywhere yet.

### 6. Escalate to the web

Below the uncovered-aspects block (or the abstention message), find the three escalation
options. Click **Search the web**.

**You should see:** the button's caption change to "sending your question now", then — once it
resolves — either an answer appears below (continue to step 7), or the caption reads "could not
reach the web" / "sent — nothing found on the web either" (see Known gaps if so).

### 7. Read the mixed answer

Assuming step 6 produced an answer, **you should see**, in this order below the uncovered block:

- The original answer text and its margin card, **untouched** — still showing "30 days" cited to
  `notice-policy.txt`.
- A **new block of prose** below it (the escalation's own answer, about the statutory minimum),
  with its own claim(s) underlined/highlighted the same way as ordinary cited claims.
- A **dashed, `--inferred`-bordered region** headed "From the web — not your files", listing one
  or more results with domain, title, a quoted passage, and a "Retrieved <date>" line.

Confirm the web answer's claims are **not** in the right-hand margin and the original document
claim is **not** in the dashed web region — the two never blur into one list.

### 8. Hover a document claim, confirm only its own margin card raises

Hover your mouse over the "30 days" sentence in the original answer. **You should see:** only
the `notice-policy.txt` margin card visually raise (e.g. highlighted border/background). The
web-results region below is completely unaffected — no card there raises.

### 9. Hover a web claim, confirm only its own web card raises, never a margin card

Hover your mouse over a sentence in the new (web-sourced) prose block. **You should see:** the
corresponding card in the dashed web region raise. **You should see:** nothing in the
right-hand provenance margin raises — the document's "30 days" card stays exactly as it was.

### 10. Repeat both with the keyboard

Click into the page, then `Tab` to the "30 days" claim span (or click it once, then use `Tab`
from there). **You should see:** the same raise behaviour as hovering, from focus alone. Continue
tabbing to the web-sourced claim span and confirm its own web card raises, and the margin card
does not.

### 11. Confirm a web result agreeing with a document does not join the margin

Read the web-region result(s) from step 7. Even if a page happens to also state a 30-day notice
period (agreeing with your document), **you should see** it stay in the dashed web region,
never copied or moved into the right-hand margin — the margin's one card is still exactly
`notice-policy.txt`.

### 12. Confirm the escalation is per-question, not sticky

Ask a brand-new question — one your document also does not cover, and unrelated to notice
periods, e.g. "What is the boiling point of water at sea level in Celsius?" **You should see:**
this new turn abstain (or partial) exactly as before, with the same three escalation options
offered again, freshly — no web answer appears automatically, confirming nothing about the
prior escalation was remembered as a default.

### 13. Ask a question entirely answerable from your document, confirm no web region renders

Ask: "How many days notice must a probationary employee give?" **You should see:** an ordinary,
fully-grounded answer citing `notice-policy.txt` ("7 days"), with **no** escalation offer beneath
it (nothing was uncovered) and **no** dashed web region anywhere on the turn.

### 14. Resize below the breakpoint, confirm the two stay visibly distinct

Return to the mixed-answer turn from step 7. Narrow the browser window past the app's `@5xl`
container-query breakpoint (roughly `1024px`). **You should see:** the margin's card reflow
inline beneath the answer (`M1-CITE-FE-044`'s existing behaviour), while the dashed web region
stays exactly as it was, its own separate block — the two remain visibly two different things at
any width.

## Known gaps

- **Depends on reachable internet and a live `ddgs` search.** If the test machine cannot reach
  the web, step 6 will show "could not reach the web" (`status: "unavailable"`) rather than an
  answer, and steps 7–11 and 14 cannot be exercised. This is `askwell.websearch`'s own
  degrade-rather-than-fail path, not a defect of this ticket — re-run with connectivity to
  complete those steps.
- **Search result content is not controlled by this test.** Unlike `M6.5-WEB-FE-190`'s fixture
  data, step 6 depends on whatever `ddgs` actually returns for the live query, so exact domains,
  titles and passages shown in step 7 will vary run to run and cannot be pinned down in this
  document.
- **The "searching", "nothing found", "unavailable" and "escalation closed" states' own
  presentation are `M6.5-WEB-FE-192`**, not this ticket. This walkthrough only confirms the
  mixed-render outcome when the escalation succeeds; it does not verify the wording or layout of
  the other four rows in `web-search.md` §4.
- **Conflict handling between a document and a contradicting web page is out of scope** and reuses
  the existing document-conflict presentation (`M2-PARTIAL-BE-059`) untuned. This walkthrough's
  document and the likely web results do not contradict each other, so the conflict path is not
  exercised here.
- **An answer entirely from the web (no document half at all) is not covered by this
  walkthrough** — every question asked above scopes to a corpus with at least one relevant
  document. The acceptance criterion that the margin explicitly states "empty" rather than
  disappearing when nothing is documented is asserted by `web-search.md` §4's "Answered from the
  web" row but not separately walked here.
- **Voice is unspecified** (`web-search.md` §8) and not exercised.
