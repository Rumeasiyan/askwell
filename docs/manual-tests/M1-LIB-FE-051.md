# Manual test — M1-LIB-FE-051, empty states that teach

**Ticket:** `M1-LIB-FE-051` — Ask's first-run and suggestion states, plus the library's
empty state
**Version under test:** `0.2.27`
**Time:** about 20 minutes without native inference (Parts A–C); 10 minutes more with it
(Part D)
**Who can run it:** anyone who can paste a line into a terminal and use a browser.

**What is being checked.** Four surfaces that a person sees before they have added
anything, or before what they added is searchable yet: `AskScreen`'s `FirstRun` (no
sources), `IndexingNotice` (sources exist, none indexed), `SuggestedQuestions` (sources
ready — three questions naming real filenames and real headings/terms from the corpus,
generated by `askwell.suggestions.suggested_questions` with no model call), and
`LibraryScreen`'s `EmptyLibrary` (naming all four ways to add a source, two marked as
arriving later). None of these four may read "no items".

**Where this stops on purpose.** Conversation history has no separate empty state to
test — `docs/states-and-edge-cases.md` §7 settles that the Ask screen's own empty states
stand in for it, so Parts A–C already cover it. Memory, clarification and connection
empty states are out of scope for this ticket (see Known gaps).

---

## Before you start

### 1. Make files to test with

```
mkdir -p ~/askwell-test/suggestions
cd ~/askwell-test/suggestions

cat > supplier-agreement.md <<'EOF'
# Payment terms

Either party may terminate on ninety days written notice. Invoices are due
net thirty from the date of receipt.
EOF

cat > notes.md <<'EOF'
Meridian shipped the widgets on time this quarter. Meridian also confirmed
the next shipment for October.
EOF
```

`supplier-agreement.md` has a real Markdown heading, so its suggestion should name the
heading. `notes.md` has no heading at all, so its suggestion should fall back to a
frequent term — "meridian" appears three times and is not on the stopword list.

### 2. Point Askwell at the folder and bring up the stack

In `.env`:

```
ASKWELL_ROOTS_MOUNT=/home/<you>/askwell-test/suggestions
```

```
podman compose up -d
scripts/dev.sh db upgrade head
```

---

## Part A — first run, nothing added yet

### 3. Open Askwell with an empty corpus

Go to `http://127.0.0.1:8000`.

**Expect:** you land on **Ask**. There is no empty text box inviting a question. Instead
you see a heading "Ask your own material", a paragraph explaining what Askwell does and
that it says so rather than guessing, and a boxed card reading "Nothing added yet" with
an explanation that there is nothing to ask about until a source is added, plus one
button: **Add a source**.

### 4. Follow the one action

Click **Add a source**.

**Expect:** you land on `/sources/add/`, titled "Add a source" — the single action from
the empty state actually goes somewhere, not to a dead link.

### 5. Add the two files

Drag both `.md` files onto the window (or drop them onto the add screen). Answer the
folder question with the absolute path to `~/askwell-test/suggestions` if asked.

**Expect:** a card moves through *Detecting → Where are these? → Recording → Queued*,
ending with a sentence that two files are queued from that folder.

---

## Part B — sources exist, nothing indexed yet

### 6. Return to Ask immediately, before indexing finishes

Click **Ask** in the left rail right away, before either file finishes indexing.

**Expect:** the composer is present and usable, and below it a sentence reads
"Still indexing what you added. Questions will search it once at least one file is
ready — check the library for progress." This is not a bare spinner — there are words.
There are no suggested questions yet, because nothing is indexed.

### 7. Follow the library link from that notice

Click **library** inside that sentence.

**Expect:** it navigates to `/library/`, the same screen Part C uses next — the notice's
own link is not a dead end either.

---

## Part C — the library's own empty state, then a populated one

### 8. Undo the add, to see the library empty first

This step needs a source with genuinely nothing in it yet. If both files from step 5
already queued before you could look, skip to step 9 and treat the row you see there —
plus the definition below — as the check instead; do not manufacture an artificial
empty state by deleting the source, since deletion is a separate ticket (`M2`).

**Expect, from reading `web/components/library/library-screen.tsx`'s `EmptyLibrary`,
confirmed on a fresh install with nothing added:** the empty library shows a paragraph
explaining what a source is and that nothing has been added yet, followed by four
named routes:

- **Files** — PDF, Word, Excel, PowerPoint, text, images
- **Spreadsheet or CSV** — tabular exports
- **Database dump** — a PostgreSQL `.sql`, `.dump` or `.backup` file *(arriving later)*
- **Connect a database** — PostgreSQL, MySQL/MariaDB, SQL Server *(arriving later)*

— and one button, **Add a source**. Nowhere does it say "no items."

### 9. Watch the two files reach ready

Wait, or refresh, until both documents in the library row show as indexed.

**Expect:** the row's coverage sentence eventually reads something like "2 of 2 indexed.
You can ask about those now." — matching `M1-LIB-FE-050`'s already-tested coverage
sentence, unchanged by this ticket.

## Part D — the suggestion list, with a native inference process running

Embedding — the last pipeline stage before a document reaches `ready` — needs a native
`llama.cpp` process. If one is not running, both documents will park at `attention` with
`InferenceUnavailable` (the same limitation every ticket since `M0-MODEL-BE-019` has
recorded), `GET /suggestions` will return an empty list, and `SuggestedQuestions` will
render nothing rather than an empty prompt — which is itself worth confirming (step 12),
but the three real suggestions below need embedding to actually run.

### 10. Start native inference

```
scripts/dev.sh inference
```

Wait for both documents to reach `ready` (watch the library row, or poll
`curl -s localhost:8000/ingest | python3 -m json.tool`).

### 11. Return to Ask

Click **Ask**.

**Expect:** the composer is focused, and below it a small label reads "From what you
have added", followed by a short list of clickable questions:

- One naming `supplier-agreement.md` and the real heading — "What does
  supplier-agreement.md say about Payment terms?"
- One naming `notes.md` and the real term — "What does notes.md mention about
  meridian?"

Fewer than three appear because only two documents exist — the list is not padded with
a generic third question.

### 12. Click a suggestion

Click the `supplier-agreement.md` question.

**Expect:** the composer fills with that exact question text and is not sent
automatically — clicking loads the question for you to review or edit, it does not ask
it on your behalf.

### 13. Send it

Click **Ask**.

**Expect:** the turn starts — named steps appear ("searching your files…" or similar)
before an answer streams in, citing `supplier-agreement.md`. If no native inference
process reached this point in your environment, expect instead the turn to fail with
"The assistant is unavailable" — a named failure, not a silent hang — which is the
`Model unavailable` state from `docs/states-and-edge-cases.md` §5 rather than a defect
in this ticket.

## What was checked against the ticket's acceptance criteria

- Ask with no sources shows the teaching state and one action, not an empty input —
  Part A, steps 3–4.
- Sources exist but none are indexed — the indexing notice says so rather than
  suggesting unanswerable questions — Part B, steps 6–7.
- Sources ready — three (here, two — the corpus only supports two) suggestions naming
  real files and real terms — Part D, step 11.
- A corpus too small for three suggestions shows fewer, not padded with anything
  generic — Part D, step 11 (two documents, two suggestions).
- The library empty state names all four routes, with the two arriving later marked so
  — Part C, step 8.
- No empty state reads "no items" — checked at every state above.
- Suggestions are generated without a model call at exactly the moment the machine may
  be busy indexing — confirmed by reading `api/src/askwell/suggestions.py`: it is two
  bounded SQL queries and a stopword-filtered word count, and `api/tests/test_suggestions.py`
  covers the heading-beats-term, no-heading-no-content, indexing-document-invisible, and
  too-small-for-three cases against a real Postgres.

## Known gaps

Do not report these as defects — they are out of scope for this ticket:

- **Memory's pre-population empty state does not exist yet.** The ticket's own scope
  says "where it is reachable" — the memory screen is not reachable enough yet to build
  this, and it is explicitly out of scope here.
- **Clarification and connection empty states** arrive with their own screens, not this
  one.
- **The first-run sequence itself** (a guided walkthrough beyond this screen's own empty
  state) is `M1-LIB-FE-052`, a separate ticket.
- **Suggestions are heuristic, not curated** — a document whose most frequent
  non-stopword term is dull (a proper noun repeated by accident, say) produces a dull
  question. This is the ticket's own stated known gap, not a defect to file.
- **No component test infrastructure exists in this repo** (`web/package.json`'s `test`
  script has no DOM/jsdom) — `SuggestedQuestions`' and `EmptyLibrary`'s render logic is
  exercised here, live, and by `scripts/dev.sh web-check`'s build/lint/typecheck, not by
  an automated component test.
