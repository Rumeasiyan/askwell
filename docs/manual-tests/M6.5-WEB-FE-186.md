# Manual test — M6.5-WEB-FE-186, the escalation offer on the abstention surface

**Ticket:** `M6.5-WEB-FE-186` — below every abstention (and below a partial answer's named gap),
three equal-weight options, each stating its own cost: **Search the web**, **Ask a larger
model**, **Add a source instead**. Never above the abstention statement. Nothing pre-selected,
auto-focused, or reachable by the Enter key that submitted the question. Accepting the web option
is a decisions-store record (C6); offering costs nothing and is not recorded.

**Version under test:** `0.6.15`
**Time:** about 40 minutes, with a native inference process running.

**What is being checked.** `web/components/ask/ask-screen.tsx`'s `EscalationOffer`,
`EscalationOption`, and `AbstentionState`/`AnsweredContent`'s use of it; `web/lib/web-search.ts`'s
`webSearchAvailable`, `escalateWebSearch`, `recordWebSearchOfferMade`,
`recordWebSearchOfferAccepted`; and, on the server, `GET /settings/web-search` and
`POST /ask/{message_id}/escalate/web` in `api/src/askwell/websearch.py`.

---

## Before you start

```
cd ~/external/quantum-plus/askwell
```

If you have never run Askwell before:

```
cp -n .env.example .env
```

Open `.env`, find `POSTGRES_APP_PASSWORD`, and put any word after the `=` if it is blank. Leave
`ASKWELL_WEB_SEARCH_PROVIDER` exactly as `.env.example` left it (empty) for Parts A–C below —
the unconfigured state is one of the things being checked. Part D turns it on.

## Cold start

### 1. Build the interface

```
scripts/dev.sh web-build
```

**You should see:** a Next.js build finishing with a route list and no red error text.

### 2. Bring the stack up

```
podman compose up -d
```

**You should see:** `postgres`, `redis`, `egress-proxy`, `api`, `worker` reported as started.
Wait about thirty seconds.

### 3. Create the database tables

```
scripts/dev.sh db upgrade head
```

**You should see:** migration lines finish with no error.

### 4. Start native inference

```
scripts/dev.sh inference
```

Leave this running in its own terminal. **You should see:** the process report a loaded model and
stay running. If no model is configured in this environment, skip to **Part E** and read "Known
gaps" — the offer only appears after a real abstention, which needs a real retrieval pass.

### 5. Open Askwell

Open a browser at:

```
http://127.0.0.1:8000
```

**You should see:** the **Ask your own material** first-run page.

### 6. Add a source with a narrow, checkable topic

Click **Add a source**. Add one file about a specific, narrow topic (e.g. a single-page PDF
about a return policy). Wait for it to reach `ready` — its row in the ingest progress list stops
showing a spinner.

### 7. Return to Ask

Click **Ask** in the left strip (or the Askwell wordmark).

## Part A — the offer is absent from an ordinary answer

### 8. Ask a question the source actually answers

Type a question you know the source covers, press **Enter**.

**You should see:** streaming answer text, a populated margin, and — below the answer — **no**
"Search the web", "Ask a larger model", or "Add a source" options anywhere. The offer belongs to
abstention (and to a partial answer's named gap), not to every answer.

## Part B — reading the abstention before the offer

### 9. Ask a question the corpus does not cover

Type something clearly unrelated to what you added (e.g., if you added a return policy, ask
"What was our Q3 revenue in the Nairobi office?"). Press **Enter**.

**You should see:** the abstained state — a block of `--ink`/`--muted` text appearing at once,
not streamed.

### 10. Read the abstention text fully before looking at anything below it

**You should see:** the three abstention lines (situation, proof of search, next action) exactly
as `M2-ABSTAIN-FE-055` described them. Confirm nothing from the offer is visible above or
interleaved with these lines — the offer sits in its own region entirely below them.

### 11. Look at the region below the abstention text

**You should see:** three boxed options, side by side (or wrapped, at this width), each showing
two lines — a bold label and a smaller cost caption underneath, in this order:

1. **Search the web** — cost reads *"sends your question out · this question only"*.
2. **Ask a larger model** — cost reads *"uses credits · you have none"*. The button looks
   visibly disabled (dimmer, ~60% opacity).
3. **Add a source instead** — cost reads *"keeps the answer in your own material"*.

**You should not see:** any option visually emphasised over the others (no filled/primary button
styling on one and outline styling on the rest), any option pre-checked, or any text suggesting
one option is recommended.

### 12. Confirm nothing was pre-selected or auto-activated

Reload the page (or open the conversation fresh) is not necessary — just confirm by eye that
none of the three buttons carries a focus ring on page settle, and that pressing **Enter** again
right now (with focus wherever it landed after step 9's submission, not clicked into any button)
does **not** trigger any of the three options. Check the browser's network tab (or just watch for
any change in the "Search the web" cost text) — nothing should fire.

## Part D — "Search the web," configured

### 16. Stop the stack and turn on the fixture provider

```
podman compose down
```

Open `.env`, set:

```
ASKWELL_WEB_SEARCH_PROVIDER=fixture
```

```
podman compose up -d
```

Wait about thirty seconds, then reopen `http://127.0.0.1:8000` and re-add the same source if the
corpus shows empty (a fresh `podman compose down`/`up` does not drop the database — the source
from step 6 should still be `ready`; only add it again if it is not).

### 17. Ask the same uncovered question from step 9 again

**You should see:** the abstained state again, with the three options below it. This time the
**Search the web** option's cost still reads its default "sends your question out" text — the
availability check (`GET /settings/web-search`) has not yet resolved to changing that text; it
only affects whether the button is enabled.

### 18. Click **Search the web**

**You should see:** the cost caption on that button changes immediately to *"sending your
question now"*, then, once the request resolves, to one of:

- *"sent — this question only"*, if the fixture provider happens to have a recorded result for
  your exact question text (unlikely unless you seeded one), or
- *"sent — nothing found on the web either"* — the expected outcome, since
  `FixtureWebSearchProvider` has no entries for an arbitrary question.

**You should not see:** the button re-enable itself or reset — the outcome caption stays until
you leave or re-ask.

### 19. Confirm the acceptance was recorded as a decision

```
scripts/dev.sh psql -c "SELECT event_type, payload FROM audit_decisions WHERE event_type = 'web_search_escalation_accepted' ORDER BY id DESC LIMIT 1;"
```

**You should see:** one row, `event_type` = `web_search_escalation_accepted`, with a `payload`
containing your question text and a `message_id` — the offer itself cost nothing to render, but
accepting it left a decisions-store record, per this ticket's own Audit/Logging requirement.

### 20. Escalate a second time on the same turn

Click **Search the web** again on the same abstained turn (it is still enabled — nothing here
remembers the prior click past showing its own outcome).

**You should see:** the sequence from step 18 repeats — "sending your question now" then a new
outcome — and a second row appears in `audit_decisions` for step 19's query. A second escalation
is a second, independently authorised act, not blocked or silently ignored.

### 21. Turn the provider back off

Stop the stack, remove `ASKWELL_WEB_SEARCH_PROVIDER=fixture` from `.env` (or blank it), and bring
the stack back up, so the rest of this walkthrough (and any other ticket's) returns to the
unconfigured default.

```
podman compose down
```

Edit `.env` so `ASKWELL_WEB_SEARCH_PROVIDER=` is blank again.

```
podman compose up -d
```

## Known gaps

- **"Ask a larger model" does nothing beyond showing itself disabled.** The real online-AI path
  is `M8`; this ticket only had to state the cost ("uses credits · you have none") and keep the
  control inert.
- **No entry point exists for escalating on a question the corpus already covers.** Deliberate —
  every obvious location is a composer control, and C10 forbids one there. Not a defect.
- **Voice escalation is unspecified and deferred** (`docs/web-search.md` §8). This walkthrough
  only covers a typed question.
- **The "Searching"/"Answered from the web"/"Escalation closed" states, and the separate
  from-the-web region, are `M6.5-WEB-FE-192` and `M6.5-WEB-FE-190`, not this ticket.** What this
  walkthrough exercises stops at the button's own cost caption changing to "sent" or "could not
  be sent" — nothing here renders an actual web citation or result card.
- **The fixture provider ships with no recorded results**, so step 18 will almost always land on
  "nothing found on the web either" rather than "sent — this question only." Both are real,
  distinct, correctly-rendered outcomes — do not report the "no results" branch as a defect.
- **Whether the offer appears at all depends on real retrieval and a real model.** Without
  `scripts/dev.sh inference` running, this document cannot be exercised past Part A.
- **No component test infra exists in this repo** (`web/package.json`'s `test` script runs
  `node --test` over `lib/*.test.ts` only) — this walkthrough is the only place `EscalationOffer`
  and `EscalationOption` are exercised in a browser; `scripts/dev.sh web-check` only confirms the
  build compiles, lints, and passes the `lib/` unit tests.
