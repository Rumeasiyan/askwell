# States and edge cases

The behaviours `docs/PRD.md` specifies, expressed as **states a user can actually be in**. The PRD says what Askwell does when things work and states several rules about what it must not do. This document covers the rest: empty, loading, partial, denied, expired, degraded, and failed.

This is the document that separates a demo from a product. It exists because "the system abstains when retrieval is below threshold" (C5) is a rule, and "the user sees a screen saying their files do not cover this, naming what to add" is a product.

**How to use this:** every screen spec must account for the states listed for its surface. A screen design that only shows the happy path is not finished.

Every product decision this document surfaced has now been answered — see §8. When you find a new state, add it here; if it needs a decision, file it rather than picking a default.

---

## 1. Global states

Apply on every surface.

| State | What the user sees | What the system does |
| ----- | ------------------ | -------------------- |
| **Offline / no network, local mode** | Nothing. No indicator, no banner | This is the design point, not a degraded state. **Never render an offline warning** — it implies something is broken when the product is working exactly as promised (C1) |
| **Web search asked for, one question** | Named progress while the question is out; results in their own marked region; a closing note that the next question starts local | C10. Offered only after abstention, never fired automatically — that rule is what keeps abstention meaningful |
| **Web search unavailable** — offline or provider down | *"I can't reach the web right now."* The abstention still stands and is still the answer | Failing to escalate is not failing to answer. The honest answer was already given |
| **Online AI enabled for a conversation** | A marker inside the composer's sticky band, never scrolled away and never dismissible: *"Online AI is on for this conversation until 18:40. Questions go to …"*. The version line at the top of Ask stops saying *"nothing leaves this machine"*. The statement of what will be sent comes *before* the first send and must be confirmed | C1. The user must never discover after the fact that content left the machine. `M8-ONLINE-FE-171`. The confirmation is a decisions record (`online_ai_disclosure_confirmed`) naming the conversation and the statement's version |
| **Online AI enabled, and what it sends is not defined yet** | The disclosure says the payload is not yet defined and that nothing will be sent. Its only action is **Switch back to local**. The Ask button is disabled, the draft is kept, and a line beside it says why | `M8-ONLINE-FE-171`. Unreachable since `M8-FIX-BE-178` set the wording (#737), and kept, because `DISCLOSURE = None` is how a statement that stops being true gets withdrawn. The server refuses too: `POST /ask` answers `409` and records nothing, and `askwell.ask._online_client` never builds a provider client. The product never sends something it cannot describe |
| **Online AI enabled, statement defined but not yet confirmed for this conversation** | The statement, **I understand. Send my questions online**, and **Switch back to local**. The send stays refused until confirmed | `M8-ONLINE-FE-171`. Confirmed once per conversation and per statement version. A conversation switched online mid-thread gets it before its first online send. A changed statement is asked again |
| **Conversation switched online mid-thread** | Earlier turns read *"Answered locally"*. Later ones read *"Answered online · <model>"*, or *"Answered locally"* when that turn stayed local | `M8-ONLINE-FE-171`. Read from each turn's `model_identity`, captured at question time. Also covers database, tool-loop and web answers, which stay local in an online conversation (#734) |
| **Online AI enabled, and the question abstains** | The ordinary abstention. Nothing is sent | The trace's backend reads `local`, with `requested: online` and `sent_online: false` (`M8-ONLINE-FE-171`). Abstention is decided before generation, so nothing goes beyond what the disclosure covered |
| **Online AI authorisation ended without the user turning it off** — its time bound lapsed, or Askwell restarted | The conversation reads as local again, and a record of why is in the decisions log. Nothing renews it silently; the user switches it back on if they are still working. The marker changes to *"Online AI was on in this conversation earlier. It is local now: nothing you ask here leaves this machine."* The screen rereads it every minute while online and after every turn. Switching back on does not ask for the disclosure again | `M8-ONLINE-SEC-169`, `M8-ONLINE-FE-171`. An authorisation nobody re-asked for is the drift C1 forbids. A conversation does not survive a reload yet: a reload starts a new, local conversation, and a past one cannot be reopened (#199). The server keeps the marker's facts, so reopening will show it when that exists |
| **Online AI switched on with no provider key stored** — a fresh install, or after the key was removed | The server's own sentence beside the switch: no provider key is stored, so there is no provider to send to; add one in Settings; nothing has left this machine. The switch stays at **Local** | `M8-KEY-BE-173`, the `409` from `M8-ONLINE-SEC-169`. Unavailable before the send, never an error at it. The destination and model are the key's, not configuration |
| **Online AI switched on while a passphrase is set and not yet entered** | The server's own sentence: online AI is not available until Askwell is unlocked, because the provider key is encrypted under the passphrase; nothing has left this machine. The switch stays at **Local** | `M8-KEY-BE-173`. Same as every other encrypted credential (`M7-SEC-BE-151`). Settings can still say *which* provider the key is for, because that part is not secret |
| **Provider key removed while a conversation is online** | That conversation reads as local at once, and its revocation record says the key was removed. The marker reads *"Online AI was on in this conversation earlier, until you removed your provider key. It is local now: nothing you ask here leaves this machine."* Online AI reads as unavailable, with the no-key sentence, before the next question rather than failing at it. A key replaced for another provider reads *"… until you replaced your provider key with one for a different provider."* | `M8-KEY-BE-173`, wording `M8-KEY-FE-175`. The reason comes from the conversation's latest `online_ai_revoked` record (`ended_reason` on its online state) |
| **Provider key replaced with one for a different provider** | Every conversation that was online reads as local, each with a revocation record saying the key was replaced. A key replaced for the same provider takes over at the next send, and online conversations stay online | `M8-KEY-BE-173`. A grant for a provider the user no longer holds a key for is a door they did not choose |
| **Online AI turned off while a request is in flight** | The request is cancelled: the connection is cut within a second, and no further request goes out | `M8-ONLINE-SEC-169`. "Completed" would let a pooled connection keep talking after the user said stop |
| **Online AI enabled, and the provider cannot answer** — the network is unavailable, Askwell's authorisation refused, the provider rejected the key or refused the request, it is rate-limiting, or Askwell's own network gateway is not running | The answer arrives from the local model, with a named step and a closing line in the answer: *"Answered by the local model."* followed by which it was. Never an error, never a blocked question. *"The network is unavailable"* is correct here and nowhere else in the product, and only when the egress proxy tried the provider and could not reach it (its `502`). A connection that could not be opened at all is the proxy itself not running, and says so (#735). A rejected key says *"The online provider rejected your key"*, never that Askwell is broken, and never contains the key | `M8-ONLINE-BE-170`, `M8-KEY-BE-173`. The trace and the interaction record keep that online was requested, which backend answered, and the reason code |
| **Online AI enabled, and the provider rejects the key or the account is out of quota** | The turn is answered locally and closes with *"Answered by the local model."*, the provider's reason, and *"This conversation is local now."* The conversation's authorisation ends at once, recorded as `provider_rejected_key` or `provider_quota_exhausted`, so later questions are local and nothing more is sent. The marker names which it was and whose fix it is: *"… until your provider account ran out of quota. … Add more with your provider, then switch online AI back on if you want it."*, or *"… until your provider rejected your key. … Check the key with your provider or replace it in Settings, then switch online AI back on if you want it."* Never Askwell's error, never a blocked question. When the key or quota is fixed, nothing switches back on by itself: the user does, and is not asked for the disclosure again | `M8-KEY-FE-175`. Out of quota is a `402`, or a `429` whose error code is `insufficient_quota`; the body is read for that code only and never repeated. A plain `429` is a rate limit: that turn answers locally and the conversation stays online, because the next question is worth trying. Each turn's backend is on its trace and its `ask_asked` record, so a mixed conversation reads accurately turn by turn |
| **Online AI enabled, and the provider stops partway through an answer** | What had arrived is withdrawn (an `answer_reset` event), the local model answers the same prompt from the start, and the answer closes with the same *"Answered by the local model."* line. Half an online answer is never kept alongside a local one | `M8-ONLINE-BE-170`. The Ask screen clears the withdrawn text, its source cards and its memory chips on `answer_reset`, and keeps the steps (#733, fixed in `M8-ONLINE-FE-171`) |
| **Online AI enabled, and the user wants to know what left for one answer** | The turn's trace, under its backend line: **show what was sent**. Where it went, the model, the time in UTC, the size in bytes, and the parts: Askwell's instructions, the question, how many passages, facts and database notes, and a clarification answer if there was one. Then how it ended. When the provider refused or failed and the local model answered, the request is still shown, because it still left. When the connection was never made, it says *"Nothing left this machine."* | `M8-ONLINE-OBS-172`. The same entry is an `online_ai_request` interaction record, so it is also in the log export. Identifiers only, never the text: the passages are encrypted at rest when a passphrase is set, and a plaintext copy in the log would bypass that |
| **Provider key pasted with whitespace, or only whitespace** | Settings refuses it in place, before sending anything, and names the reason: only spaces or line breaks, or a space or line break picked up when copying. Never trimmed quietly, never repeated back | `M8-KEY-FE-174`. The server's own check (`provider_key.validate`) stays the authority for everything else, and its sentence never contains the key |
| **Provider key entered while a passphrase is set and not yet entered** | Settings asks for the passphrase first, in place, then shows the key form. Removing a key does not ask | `M8-KEY-FE-174`, through `POST /settings/passphrase/unlock`. The key cannot be encrypted under a passphrase this session does not hold (`423` from `PUT /settings/online-key`) |
| **First launch, nothing configured** | Guided setup: add a first source, wait for indexing, ask a first question | Install-to-first-answer is the metric most likely to kill the product (`success-metrics.md` §4) |
| **Model still downloading** | Progress with a realistic estimate. Everything else remains usable | On a slow connection this dominates first-run time |
| **Model not loaded / llm container down** | "The assistant is unavailable", with a fix path. Document browsing and search still work | Retrieval does not need the LLM. Degrade to search, not to a blank product |
| **Shell open, stack and inference still coming up** | The starting page — a named "Starting Askwell" state, not a blank window or the webview's own connection-refused page | `M7-TAURI-DEPLOY-183`. The shell now starts both rather than a user having started them first, so this state is reachable on every cold launch, briefly |
| **Container runtime missing or not running** | The starting page names it — "Podman isn't available" — with what to do, distinct from the stack simply failing to come up | `M7-TAURI-DEPLOY-183`'s third cause: Askwell cannot start Podman itself, so this is not a retryable stack failure |
| **Container stack fails to come up (backoff capped)** | The starting page names it — "The container stack couldn't start" — with the last failure reason retained | `M7-TAURI-DEPLOY-183`. Distinct from the runtime-missing state above and from the already-running-application's own per-component `M0-MODEL-BE-020` reporting, which needs a reachable API this state never reaches |
| **Supervision surface open, both halves healthy** | A calm "Both are running. Nothing needs your attention" banner — Start disabled on each half, Stop still reachable for a deliberate manual stop | `M7-PACK-FE-143`. The AC is explicit: healthy must not invite unnecessary action |
| **Supervision surface, a half manually stopped** | That half shows `Stopped`, not `Failed` — the loop does not try to bring it back until Start/Restart is pressed | `M7-PACK-FE-143`. A deliberate stop and a capped failure are different causes with different fixes, same as every other pair this document separates |
| **Supervision surface, a manual action fails** | The reason is shown inline near the button that was pressed, not a silently unchanged state | `M7-PACK-FE-143`'s own edge case: "a restart that fails — the reason is shown rather than the action silently doing nothing" |
| **Supervision surface reachable, API down** | Opens and reports from the native menu ("Askwell" → "Supervision…") regardless of whether the main window shows `starting.html` or has handed off — it never depends on the API | `M7-PACK-FE-143`. The whole point: this is exactly when it is needed |
| **Passphrase set, app restarted** | Prompt for the passphrase before anything decrypts | Optional feature; when on, it is what makes a stolen laptop not a data breach |
| **Log storage at 80% of budget** | Persistent dismissible notice offering export, archive or prune | `audit-log.md` §3 |
| **Log storage at hard limit** | **New ingestion refused**; asking questions keeps working | Ingestion is the biggest writer. Blocking the cheapest and most valuable operation last is what keeps the product usable |
| **Decisions store cannot be written** | The action fails, with a clear reason and what to free up | Issue #10, Option A — the only place a write failure stops an action |
| **Disk full** | Adding sources refused with a clear message. Existing material stays queryable | Never accept a source that cannot be durably written |

| **Narrow window** | Left rail becomes a drawer, reachable from a control in the app's own chrome. Open, it carries its own close control (it covers the one that opened it) and holds keyboard focus; the scrim, `Escape` and choosing a destination all close it. Widened past the breakpoint while open, it closes into the ordinary column rather than staying an overlay | Hiding navigation without a way back strands the user in a product where the library is the only route to sources, memory and settings |
| **Native file dialog open** | The Tauri shell's own picker, for nominating a root directory or relocating a moved file | Indexing in place makes both core paths, and neither works well in a browser tab |

There is no licence state, no seat cap, no session expiry and no permission denial. The product is free, single-user and local — none of those states exist.

## 2. Asking a question — chat

The core loop. Most of these states are reachable in the first five minutes of use.

| State | What the user sees | Why it matters |
| ----- | ------------------ | -------------- |
| **First run, empty corpus** | Not an empty chat box. A first-run state that says no documents are ingested yet, what Askwell will be able to answer once files are added, and a direct path to add the first one | An empty chat box invites a question that will abstain, which teaches the user in their first 30 seconds that the product does not work |
| **Thinking / retrieving** | Streamed progress naming the step: searching documents, reading N sources, querying the database | On the `light` profile a question can take 20s+. A silent spinner for 20 seconds reads as broken |
| **Answering** | Token streaming. Citations render as they are emitted, not appended at the end | — |
| **Abstention — nothing above threshold** | An explicit "I don't know" state, visually distinct from an answer. States what was searched, and what would need to be added to answer it, with a path to add it. **Never a hedged half-answer** | C5. This is a first-class product state, not an error. It is the state most likely to be quietly degraded later by lowering the threshold — see `docs/success-metrics.md` §2 |
| **Partial retrieval** — some claims grounded, some not | Answer the grounded part; say plainly which part is not covered | The tempting failure is to smooth over the gap in fluent prose. C4 and C5 both forbid it |
| **Tool-call ceiling hit (8 calls)** | Return what was gathered, with an explicit note that it stopped early and why. Offer to continue as a new turn | `architecture.md` §10. Silently truncating reasoning and presenting the result as complete is worse than saying it stopped |
| **Conflicting sources** | Present both, with both citations and their dates. Do not silently prefer one | `build-plan.md` quality gate has a whole eval category for this (10 tasks, ≥ 0.75); it needs a UI, not just model behaviour |
| **Conflicting sources, a document with no date of its own** | Its record says "Date unknown". The date it was added is never shown in its place | `M7-FIX-FE-170`. When Askwell ingested a file says nothing about which version is current, so showing it would be a wrong fact presented as a right one |
| **Conflicting sources, both positions from one document** | Still two records, each naming the same file | A document that contradicts itself is a conflict too. Merging the two would hide it |
| **Inline clarification blocks the answer** | Composition pauses; the question renders inline, in the conversation, with its evidence. Answering completes the answer using it; skipping continues and states the assumption used. The user is never navigated to the clarifications queue | `M3-INLINE-FE-085`. The queue is for everything else; this is the one place an ambiguity is worth interrupting for, because the wrong guess changes which fact the answer states |
| **Two blocking ambiguities in one turn** | The higher-ranked one is asked inline; the other is named as deferred to the queue rather than asked in sequence | Asking twice in one turn is the same "modal per question" pattern already rejected for ingestion (`memory-and-clarification.md` §2), moved to answer time |
| **User navigates away while an inline clarification is pending** | The question is exactly where it already was — `pending` in the ordinary queue — and the paused turn stays paused indefinitely, resuming if the same browser answers it later | Never bounced, never lost, and no timeout invents an answer nobody gave |
| **Superseded document** | Answer from the current version, stating "as of the June revision" | `data-sources.md` §1 requires this explicitly |
| **Question in a language other than English** | Say the product is English-only in this version. Do not attempt a poor answer | v1 is English-only (`PRD.md` §8). The `tam` OCR hedge means Tamil text may be *in* the corpus; that must not be mistaken for Tamil support |
| **Retrieved content or a tool result contains instruction-like text** | Answer normally; the trace flags it, per step for a tool result | C7. Flagged in the trace, not shown as a scary warning — this is a mitigation, not a detection system, and PRD §8 says to document the residual risk honestly rather than overclaim. `M5-TOOLS-BE-114` extends the same flag to a tool call's own result (a database row, a schema note) |
| **Very long answer** | Stream, do not truncate silently. If a limit is hit, say so | — |
| **User navigates away mid-answer** | Generation continues server-side and the answer is saved to the conversation | Issue #14, Option A. Costs local compute on an abandoned question — fan noise on a laptop, not a queue, since there is no other user waiting |
| **Suggested follow-ups after a completed answer** | Up to three, derived from what was just answered; fewer or none rather than padded. Click fills the composer, focused, and sends nothing | `conversation.md` §3, `M1-CONV-FE-180`. A suggestion that fires immediately takes the decision away — the point is a cheap start on the next question, not asking it for the user |
| **Suggestion clicked with a draft already in the composer** | The user is asked before the draft is replaced; declining leaves it untouched | This ticket's own edge case — a suggestion is an accelerator, never a silent overwrite of work in progress |
| **Follow-up suggestion generation fails or has nothing to suggest** | No row renders; the answer above it is unaffected | Same rule as the empty-state corpus suggestions (`M1-LIB-FE-051`): an accelerator must never be able to break an answer |

## 3. Documents and ingestion

| State | What the user sees | What the system does |
| ----- | ------------------ | -------------------- |
| **Add in progress** | Per-file progress. Navigating away does not cancel it | Ingestion is a background job (`arq`), not a request. Not an *upload*: nothing is copied anywhere |
| **A drop being read** | The count and total size at once, then "N of M" as each file's type is worked out | Only the first 4 KB of each file is read, in chunks that hand the window back — a folder of several thousand files must not freeze it |
| **A second drop while one is being read** | Queued behind the first, with its own count | Rejecting it would punish the user for Askwell being busy with their previous instruction |
| **A file named one thing and containing another** | Routed by its contents, with the disagreement stated in the name they gave it | Silence here loses a fact worth having: one of their documents is not what it says it is |
| **A program dropped among documents** | Refused by name, with the fact that nothing was run | The same instinct as C3's sandbox, applied where nothing is executed at all |
| **More files in one drop than the cap** | The number taken, and that the rest were left | A cap that truncates silently reads as "everything was added" |
| **Files queued but nothing indexed yet** | Said plainly, with what has to land before they are searchable | An honest sentence, not a progress bar that never moves |
| **Queued behind a backlog** | Position and a realistic estimate | Embedding a large corpus on CPU takes hours. An untimed spinner suggests a hang |
| **Extraction failed** (corrupt, encrypted, password-protected PDF, missing from disk, unreadable on disk) | The document is listed as failed by name with a reason distinct per cause. Retry available; a password-protected PDF prompts for its password instead, a wrong password reported as wrong with another attempt allowed | Never silently drop it (AGENTS.md §6). `M1-EXTRACT-VAL-030`: `MissingSource`/`UnreadableSource`/`CorruptDocument`/`PasswordProtected`/`WrongPassword` in `extract_common.py`/`extract_pdf.py`; `POST /ingest/documents/{id}/password` |
| **PDF with no text layer anywhere** | Reads visibly more slowly than a digital PDF, then completes with a correct page count; marked as OCR-derived | `extract` (`M1-EXTRACT-ING-026`) detects it and `M1-EXTRACT-ING-028`'s OCR pass reads every page in the same run — no separate wait, no ticket named to the user. Only if OCR itself finds nothing anywhere does the document fail, the same C5 case as any other empty document |
| **PDF with a text layer on some pages and not others** | Proceeds normally; the blank-text-layer pages are OCR'd, the rest are not | Per-page, not per-document (`M1-EXTRACT-ING-028`) — one scanned exhibit inside an otherwise digital contract only pays the OCR cost for that exhibit's own pages |
| **A scanned page that comes out upside down or sideways** | Read in the correct orientation regardless | `M1-EXTRACT-ING-028` runs Tesseract's orientation and script detection before recognition, on every OCR'd page |
| **Scanned, OCR produced little or no text** | Flag as low-confidence: the source shows needs attention with a readable, specific reason naming the file and, for a mixed document, the poor pages. Still listed as indexed, never as failed | `M1-EXTRACT-ING-029` — distinct from failure. The document exists but is nearly invisible to search, and the user needs to know. The cut line is `ASKWELL_OCR_CONFIDENCE_THRESHOLD`, configuration rather than a literal |
| **Scanned Tamil document** | Ingests via the bundled `tam` traineddata; marked as not-supported-language | `PRD.md` §8 — a hedge, not a feature. It must not appear as Tamil support |
| **Word, PowerPoint, Excel, text, Markdown or HTML with no extractable text at all** | Failed with a reason, never indexed empty | `M1-EXTRACT-ING-027`'s own validation rule — the same C5 failure as a PDF with no text layer, wearing a different cause. `extract_common.EmptyDocument` |
| **A Word document with tracked changes** | Indexed as the accepted text; the presence of unresolved revisions is logged, not marked in the citation | `M1-EXTRACT-ING-027` — `python-docx` already reads only accepted runs, so nothing here chooses between versions of the text |
| **A slide deck with speaker notes** | Included in the slide's text, labelled `[Speaker notes]` | `M1-EXTRACT-ING-027` — a retrieval hit on a presenter's own note should read as one, not as on-screen content |
| **A `.doc`, `.xls` or `.ppt` file (legacy binary Office)** | Failed by name — "Askwell does not read the older binary Office formats yet" — retryable, not silently dropped | `askwell.filetypes` already routes it as supported; none of the OOXML libraries this ticket added can open it. Issue #121 |
| **An `.md` file with YAML front matter** | The front matter is excluded from the indexed text; the prose beneath it is not | `M1-EXTRACT-ING-027` — front matter is metadata, and indexing it as prose would make a retrieval hit read like a sentence nobody wrote |
| **An HTML page saved from a browser** | Navigation chrome and the page `<title>` are discarded; only the body's content is indexed | `M1-EXTRACT-ING-027` — the `<title>` leak was found by running a real saved page through the pipeline, not designed for up front |
| **Unsupported format** | Rejected **per file**, naming the file and what its contents turned out to be, with the supported list once beneath. The rest of the drop proceeds | `data-sources.md` §1 lists formats. Per file, not per drop: one archive among sixty contracts must not take the contracts with it |
| **A format whose route arrives in a later milestone** (CSV, dump) | Named as **arriving**, with the milestone — not as unsupported, and never queued | Recognised and not-yet-built are different facts. Told "unsupported", somebody whose material is mostly exports concludes the product is not for them, which is false |
| **A drop that expands to no files at all** | Said plainly: an empty folder, nothing changed, and the supported list | An empty folder is a real gesture and deserves an answer. A cancelled file dialog produces the same empty list and must stay silent — the folder count is what tells them apart |
| **Duplicate (same sha256)** | Named as already present, linked to the existing document. Not re-ingested | `documents.sha256` exists in `architecture.md` §7 for this |
| **The same content under two names** | Both paths shown — the one indexed and the one recognised — so it is clear which copy Askwell is reading | Recognition is by content across every source, because the same contract in three folders is three sources. "Already present" without saying *where* leaves someone with three copies no better off |
| **An empty file** | Rejected by name with the reason, and the rest of the drop carries on | There is nothing to index. Detected on the size rather than on the head: a head is a slice, and every empty file and every large one look alike through one |
| **A drop where every file was already indexed** | "Nothing new here" — nothing added, nothing changed on disk, library unchanged | Not "0 files queued". A count of zero next to the word *Queued* reads as a failure, and nothing failed |
| **A file that changes while Askwell is reading it** | Re-read. If it never settles, reported per file — something else is still writing to it — and nothing is recorded | A hash taken across a file being written names bytes nobody will ever read again. The identity is checked before and after the read, and the attempts are bounded so a log being appended to does not stall a whole drop |
| **New version of an existing document** | Marked superseding the old one; the old one stays queryable for history | `data-sources.md` §1: supersede, do not duplicate |
| **Embedding job failed after retries** | Visible in the library with the error and a retry | AGENTS.md §6, explicitly |
| **Document deleted** | Old citations resolve to "deleted on `<date>`" rather than breaking | Issue #11, Option A — tombstone. Content and embedding are cleared so it stops influencing retrieval; the row survives so the audit chain and old citations still resolve |
| **Empty collection** | Empty state naming what it is for and how to add to it | — |
| **File outside every nominated folder** | Asked to nominate its folder, with the consequence explained. Not a bare rejection | Askwell indexes in place, so it has to be told which folders it may open. `ux/add-source.md` §7 |
| **Folder nominated, not yet mounted** | Accepted, with the configuration line and that the stack has to come up again — said now, not discovered | A container's mounts cannot be changed while it runs. Refusing would make a fresh install unable to nominate anything |
| **Nominated folder not connected** | Its sources report **unavailable**: a drive unplugged, a share disconnected, or — on Windows — a drive letter that changed between sessions | **Never rendered as deleted, and never as moved.** A whole folder being absent is not forty files having moved, and offering to relocate each would be forty wrong questions. A drive letter is not a stable identity across reboots on Windows, so this is the same case as a USB drive being gone, not a new one (`roots.probe`, `M7-PACK-DEPLOY-140`) |
| **A file path past Windows' length limit (MAX_PATH, 260 characters)** | Reported **per file**, as an unreadable source naming the file — not a failed drop | `extract_common`'s per-file `OSError` handling already catches this generically (the same path `MissingSource`/`UnreadableSource` take); Windows just reaches it by a cause Linux does not (`M7-PACK-DEPLOY-140`) |
| **Nominated folder cannot be read** | Named, with its permissions and SELinux labelling as the two causes | Root inside the image ignores the mode bits, so this is the case that actually bites on a Linux host |
| **Nominated folder removed** | Its sources stay listed, saying the folder was removed and that nothing was deleted | The registry tombstones rather than deletes, so "you removed this" is distinguishable from "no folder ever covered this" |
| **Folder is a network share** | Permitted, warned: indexing is slow, and the share must be connected for a citation to reopen its page | Refusing would exclude a real way of working; saying nothing would surprise someone hours in |

## 4. Database question-answering

Highest-risk surface. The customer's production database is on the other side.

| State | What the user sees | What the system does |
| ----- | ------------------ | -------------------- |
| **No connections configured** | "No database is connected. Connect one to answer questions like this from your own data, not just your documents." with a **Connect a database** action, only for a question that looks database-shaped (`M4-RESULT-FE-111`) | Abstaining as if the corpus lacks it is misleading — the data exists, it just is not connected. Fires only *after* document retrieval has already found nothing (issue #400), so a question a document actually answers is never intercepted |
| **A relevant source exists but is still importing** | "`<name>` is still importing. Try again once it finishes." — no add-source action, since adding another source does not fix this | `M4-RESULT-FE-111`. Distinguishes "wait" from "connect one" and from "it's down" — three different fixes for three different states |
| **A relevant source exists but needs attention** | "`<name>` needs attention and can't answer questions right now. Check its connection in the library." naming which, when several are connected | `M4-RESULT-FE-111`, the "several connections where one is down" edge case |
| **Sandbox instance unreachable** | Dump-backed sources show "needs attention" in the library (`ux/library.md` §5) naming the sandbox as down; document sources are unaffected | `data-sources.md` §3, C3. The sandbox is a separate container (`M4-DUMP-DEPLOY-087`) that can fail to start independently of Postgres; a dump import cannot proceed without it, but nothing about that should read as "Askwell is broken" |
| **Connection wizard: credentials pass the write probe** | Refused, naming which permission was detected | `data-sources.md` §4 — the wizard refuses write-capable credentials. Not a warning, a refusal |
| **Connection dead at query time** | "The database is unreachable", not a generic failure. The user sees the connection error, since there is no one else to see it | Customer DBs go down independently of Askwell |
| **Generated SQL rejected by `sqlglot`** | The user sees a normal "I could not answer that safely" and the SQL is **shown**, since disclosure is unconditional | C2. The rejection is logged with the offending SQL — this is the signal that a prompt change has degraded generation, and it must be visible |
| **`EXPLAIN` dry-run fails** | Same as above; the query is not executed | `data-sources.md` §4 |
| **Query exceeds `statement_timeout` (30s)** | "The query took too long", with the SQL and a suggestion to narrow it | `data-sources.md` §4 layer 4 |
| **`LIMIT` auto-injected** | Result is labelled as showing the first N of possibly more, with the injected limit visible in the SQL | `data-sources.md` §4 layer 3. A silently truncated result an analyst believes is complete is a wrong answer with no warning attached |
| **Zero rows** | "No matching records" — with the SQL, so the analyst can see whether the question or the query was wrong | Distinct from an error and from abstention |
| **Very large result** | Paginated, with the row count | — |
| **Schema drift** — annotated table or column no longer exists | Admin console flags stale annotations | Otherwise the model is prompted with a schema that no longer matches reality |

## 5. Voice

| State | What the user sees / hears | Notes |
| ----- | -------------------------- | ----- |
| **Microphone permission denied** | Voice mode disabled with an explanation and a path to re-enable in the browser | Browser permission, not something Askwell can fix |
| **No input device** | Mic control states there is no microphone, rather than being silently unresponsive | `M6-VUI-FE-128a`. Distinct from permission denial: nothing to grant, nothing the browser's site settings can fix |
| **A second press while transcribing or answering** | Ignored | `M6-VUI-FE-128a`. Not a second socket — the control only knows how to leave idle |
| **No speech detected** | Silent timeout back to idle. No error sound | Silero VAD (`build-plan.md` Phase 5) |
| **STT confidence low** | Show the transcription and ask for confirmation before answering | Answering the wrong question confidently is worse than one extra tap |
| **TTS unavailable** | Answer is delivered as text with a note that the voice is unavailable | Voice is a mode, not a separate product (`build-plan.md` Phase 5) — falling back to text is correct |
| **WebSocket drops mid-turn** | Reconnect; if the answer completed server-side, deliver it in the conversation | The turn is in the audit log regardless |
| **Latency budget missed** | An indicator appears, only once the budget is already passed | Issue #15, Option B. Costs nothing on a healthy turn; prevents the user concluding it has hung and retrying |
| **User speaks over the answer** | No barge-in. A visible stop control ends the answer | Issue #13, Option B — solves "I cannot escape this answer" at a fraction of the cost |

## 6. Settings, memory and the log

There is no administrator. These are the user's own settings.

| State | What the user sees | Notes |
| ----- | ------------------ | ----- |
| **Pending clarifications waiting** | A count, not a modal. Reviewable whenever they choose | Never block on questions (`memory-and-clarification.md` §2) |
| **Clarification answered** | Confirmation of what changed, and that affected material is being re-processed | The user must see that answering did something, or they stop answering |
| **Memory inspection** | Every fact Askwell believes, with origin, date and an edit or delete control | A memory the user cannot inspect is a system that gets mysteriously worse and cannot be debugged |
| **Memory fact superseded** | Old value visible in history, not erased | Corrections supersede; they never overwrite |
| **Memory fact from a deleted source** | General facts survive and say "learned from a source you deleted"; structural facts (schema notes) go with the source | `M3-MEM-FE-083`. `askwell.sources.delete_source` deletes a source's `schema_notes` outright but only soft-deletes the source row, so a general `memory` fact's `source_id` still resolves and can be labelled |
| **Memory fact unused** | Shown with "used in 0 answers", never auto-deleted | `M3-MEM-FE-083`. It may be waiting for the right question — deleting it silently would discard something the user supplied |
| **Log export, large range** | Background job with progress and a download when ready | A year of interactions is not a synchronous operation |
| **Log verification finds a broken hash chain** | Reported plainly, naming where the chain breaks | C6 is tamper-*evident*. This is that evidence, and it must be surfaced, not swallowed |
| **Model swap in progress** | Assistant unavailable with expected duration. Retrieval still works | `M7-SET-FE-146`: stated in the confirmation before the swap starts, and again while it runs. Questions asked meanwhile wait, and are not refused |
| **Model swap to an unverified model** | The statement that citations and "I don't know" are not guaranteed, shown in the confirmation every time, with no "don't show again" | `M7-SET-FE-146`. `POST /model/select` refuses an unverified swap whose request does not say the statement was shown. Permitted, never blocked |
| **Model swap requested while another is running** | Refused, naming that another swap is running and that nothing changed | `M7-SET-FE-146`, issue #675. Refused rather than queued: the second request is a second tab or a stale click, and queueing it would swap again after the first finished |
| **Model swap fails to load** | The failure named, and that the previous model is back in use | `M7-SET-FE-146`. The host supervisor restores the previous model; nothing is persisted |
| **No other model file present** | "No other model file", with the folder to place one in, named as the user knows it | `M7-SET-FE-146`. Never `/models`, the container's view |
| **Throughput before any answer from this model** | "Not measured yet", never `0` | `M7-SET-FE-146`. The figures are per model, so a swap starts this state again |
| **Memory not measurable** | "Not measured", with the model file's size alongside for scale | `M7-SET-FE-146`. The assistant is not running, or the platform has neither `/proc` nor `ps` |
| **Hardware below the `light` floor at install** | Warned, with what to expect, and allowed to continue | **Warn, do not refuse.** Refusing made sense for a paid deployment that could be blamed on the vendor; for a free download it is just a lost user |
| **Hardware probe fails to detect memory at all** | Named as a probe failure, distinct from a below-floor reading, with the `standard` fallback stated. Allowed to continue | `M7-PROBE-FE-138`. Conflating this with the below-floor warning would lose both the concrete GB numbers the below-floor case has and the fact that a re-probe on this machine might land anywhere — it is not known to be small, only unmeasured |
| **Hardware profile overridden in settings to one the machine cannot support** | Permitted, with the consequence stated before the change; if a model then fails to load, the assistant reports that failure clearly and document search keeps working | `M7-PROBE-FE-138`. Never refuses on hardware grounds — the ticket's own Validation Rule. A genuine re-probe still overwrites the override the next time it runs |
| **Online AI in Settings** | Words only: where it is turned on (beside a conversation's Ask button, one conversation at a time, every new one local), what it is, that the key and the bill are the user's own, and that what leaves the machine is stated in the conversation before anything is sent. **No switch** | `M7-SET-FE-150`, then `M8-ONLINE-FE-171`, which removed the inert switch because a switch here reads as the global setting that must not exist. No field collects anything and nothing in the section makes a request. `M8-KEY-FE-174` adds the key |
| **Abstention rate rising** | Surfaced with the unanswered questions driving it | That list is what to add next |
| **Per-source index size for a connection or dump source** | "Unknown", never "0" | `M7-SET-FE-148`. A connection or dump is queried in place and never chunked or embedded, so there is no index to size — reporting `0` would read as "this holds nothing", which is false |
| **Per-source index size while a source is still queued or indexing** | "Unknown", never "0" | `M7-SET-FE-148`. Nothing measurable exists on disk yet; `0` would read as "this source is empty" rather than "not indexed yet" |
| **Log budget's effective figure capped by 5% of free disk** | The configured cap and the smaller effective cap both shown, with the free-disk figure that is doing the capping | `M7-SET-FE-148`, issue #484. `budget_bytes` alone cannot say whether it reflects what the user set or free disk overriding it — `configured_bytes` is what makes the difference visible |
| **Log budget lowered below current use** | Accepted; the immediate consequence (ingestion refused at this cap) is stated, and export-and-prune is pointed to | `M7-SET-FE-148`'s own Edge Case. The change is never refused for being "too low" — the same "state, do not block" pattern the retrieval threshold uses |
| **Retention window changed** | Confirmed, with an explicit statement that nothing is pruned by the change itself | `M7-SET-FE-148`. The value is a real decisions record; `M7-LOG-BE-154` built the prune that reads it, but changing the window is still never itself a prune — a change alone does not delete anything until Export and prune is run |
| **Prune attempted with nothing exported to cover it** | Refused, with export offered as the fix | `M7-LOG-BE-154`. `askwell.log_prune.enqueue` raises `PruneNotExported` unless a completed, unfiltered log export already covers the window — pruning an interaction the user never got a copy of destroys part of their own history with no way back |
| **Retention window short enough to prune nearly everything (≥90% of what exists)** | An explicit "this removes nearly everything" confirmation, not a silent prune | `M7-LOG-BE-154`. `askwell.log_prune.enqueue` raises `PruneRequiresConfirmation`, the same "state the consequence once, then allow it" pattern `settings.md` §2 already uses for an unvalidated model |
| **Prune interrupted mid-run** | Resumable, chain intact either way — nothing is shown as half-pruned | `M7-LOG-BE-154`. The delete and the decisions record that explains it are one transaction, so a crash leaves either everything or nothing; `askwell.worker.startup`'s `resume` returns the job to `queued` and a retry is not distinguishable from running once |
| **Log verification, after a legitimate prune** | Reported intact, with a note explaining where the chain now starts and why | `M7-LOG-BE-154`, issue #516. Without this, `askwell.audit.verify` would report the exact shape a real deletion produces — a false positive baked into a ticket that shipped before its own dependency existed |
| **Export and prune, wiring the settings screen to the real endpoints** | Export is wired, under Your data (`M7-DATA-FE-160`). Prune still has no settings-screen entry point, and Storage's combined export-and-prune control stays disabled until it does | Same pattern `settings.md` §3 uses for Online AI ahead of M8 — visible and honest rather than hidden or silently broken |
| **Export everything with a passphrase set** | Warned that the export will not be protected, before anything is written; "Export without protection" or Cancel | `M7-DATA-FE-160`. The backend refuses independently until acknowledged (`askwell.log_export.ExportNotAcknowledged`), so the warning cannot be skipped by a stale screen |
| **Export everything running** | Progress in log records, then "writing sources, memory and conversations", and that it runs in the background | `M7-DATA-FE-160`. Leaving the screen stops the polling, not the job |
| **Delete all memory with none held** | "Askwell holds no memory. There is nothing to delete." — no confirmation offered | `M7-DATA-FE-160`. A confirmation for zero facts would ask the user to agree to nothing |
| **Delete all memory after memory changed since the count was shown** | Refused with "Memory changed since you confirmed", nothing deleted; counting again is one click | `M3-MEM-FE-084`'s `expected_count` check, reused |
| **Reset confirmation** | The original-files statement first, then what is removed as counts in the user's nouns, that the log recording the reset goes too, and that it cannot be undone | `M7-DATA-FE-160`. Registered folders are named as *forgotten*, never as deleted |
| **Reset while ingestion is running** | Nothing different: the confirmation says anything being added is stopped first | Reset's table locks wait for the in-flight write; what the worker does next finds no row (`askwell.reset`) |
| **Reset done, a file could not be removed** | Named by path in the outcome, never hidden | `M7-DATA-FE-160`, issue #683 |
| **Reset done, sandbox unreachable** | "Imported database copies could not be reached just now. They are removed the next time Askwell starts." | The worker's startup reclaim drops every sandbox database no source claims |
| **After a reset** | The outcome, the original-files statement again, and "Start again", which reloads the page | Reset deletes the session secret with `settings`; only a full page load gets a new session. Any other section still open on the page answers "No session" until then |
| **About — a bundled dependency or model licence changes** | Nothing visible until the next build; `NOTICES.md` and `web/public/notices.md` are generated and checked by `scripts/dev.sh notices`, not hand-edited | `M7-DOC-DOC-163`. A disallowed licence blocks the release gate (`docs/release-procedure.md`), not this screen — the screen only ever shows what the last successful build shipped |
| **About — the source or issue-tracker address while offline, or in the desktop shell** | The address is shown as selectable text with a "Copy address" button, so it can be opened elsewhere. The desktop shell denies every `target="_blank"` (`web/src-tauri/src/main.rs`, `on_new_window`), so a link alone is a dead control there. | **About — report a problem while offline** | The support boundary is shown in the page, in full, before the issue address; the security policy opens in place the same way. Only opening the issue tracker needs one | `M7-DOC-DOC-164`. Someone offline is often exactly the person with a problem; the part that sets their expectation must not depend on the network the product promises not to need |
| **About — someone with a security problem** | A separate, named row ("Security problem — report privately, not as an issue"), never the general "Report a problem" link | `M7-DOC-DOC-164`. A vulnerability filed through general triage is already publicly disclosed by the time it is triaged |

| **About — never checked** | No line, and nothing that reads as a failure | `M7-UPDATE-FE-162` |
| **About — a version found before its date was recorded** | The version, with no date | `M7-UPDATE-FE-162`. A version found by a build before `0.7.34` has no stored date, and one is never made up. The date appears when the next version is found |
| **About — check now** | "Checking now makes that same one request, once, even if weekly checking is off", then the button. ## 7. Empty states, collected

Every one of these is a real screen someone will see on day one, and each is an opportunity to teach the product rather than show a blank box:

| Surface | Empty state must say |
| ------- | -------------------- |
| Chat, no corpus | Nothing ingested yet; what will be possible once it is |
| Document list | What a collection is for; how to upload |
| Collection, no documents | Same, scoped |
| Database connections | What connecting enables; that credentials must be read-only |
| Memory, before anything is learned | What the clarification loop will do, and that answering questions makes answers better |
| Conversation history | Nothing asked yet this session. There is no separate history screen before turns collapse (`../ux/conversation.md`, `M1-CONV-FE-178`) — the Ask screen's own empty state stands in for it: the suggestion list once a corpus is indexed, or the indexing notice while it is not (`M1-LIB-FE-051`) |
| Audit log, filtered to nothing | Distinguish "no events" from "filter excludes everything" |
| Usage dashboard, pre-traffic | What will appear once questions are asked |
