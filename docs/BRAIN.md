## Last completed

**`M1-ADD-ING-025`** — indexing stops belonging to the page you are looking at. `0.2.6`. Issue [#111](https://github.com/Rumeasiyan/askwell/issues/111).

Recording a drop now writes a queue row per document in the same transaction as the document, and a worker drains it. The add request ends; the work does not.

Four things this ticket decided rather than assumed, two of them in `decisions.md`:

- **Postgres is the queue's record; Redis is only its transport.** `arq` wakes a worker and nothing more. A job that exists only in Redis is lost by `podman compose down -v`, by a worker killed mid-job, by a laptop suspended for two days and by an enqueue that failed after the documents were committed — and none of those produces an error anywhere. `resume()` at worker startup returns interrupted jobs; a reconcile cron every thirty seconds repairs the rest. A failed dispatch is a delay, never a lost import, and never a failed request.
- **A stage that has not been built is `parked`, not finished and not failed.** The pipeline declares `extract`, `chunk`, `embed` with their tickets and installs none. A job runs, reaches extraction, finds nothing there and stops, saying which stage and which ticket. `ready` would tell retrieval a document has passages it has not got; `failed` would turn a fresh install's whole library red for no reason. Parked is what `states-and-edge-cases.md` §3 already asked for.
- **A source's status is derived from its documents, not from a job being claimed.** The first version read `indexing` off a claimed job, and with no stage installed a job is claimed and parked inside a millisecond — so three files flicked the source `queued` → `indexing` → `queued` and wrote six decisions records about work that never happened. Caught by running it, not by a test; there is a test now.
- **Askability is a coverage figure, not a status.** A source with fifty-eight of sixty files readable and two failed is `attention` — that is the only place the library has to offer the retry — *and* askable, because fifty-eight papers' worth of answers should not wait for two corrupt ones.

**Verified on the stack**, not just in tests: three files added with the worker stopped, `GET /ingest` reporting them queued at positions 1, 2, 3 with the honest "no estimate yet" basis; one job forced to `running` and Redis then flushed entirely; the worker started, logging `ingest_resumed_interrupted documents=1` and `worker_resumed dispatched=3 interrupted=1`, and all three completing. `curl -N /ingest/stream` held open across a fourth file being added received two events — the snapshot and the change — and nothing in between. The migration's backfill was observed picking up a document recorded by `M1-ADD-BE-023` before the queue existed.

**What is not demonstrable yet, stated plainly:** no document reaches `ready`, because nothing extracts. Progress advancing per file, progress inside a file, failure with a retry, and partial coverage are proved by tests that install a stage of their own; a walkthrough today ends at "recorded and waiting" with the missing stage named. That is the ticket working as scoped, not a gap in it — but it is why the cold-start walkthrough in the ticket cannot be run end to end until `M1-EXTRACT-ING-026`.

**`M1-ADD-BE-023`** — Askwell remembers what it was given, and notices when it has been given it before. `0.2.5`.

A queued batch stopped being a list in a browser tab. `POST /sources` creates one source for the folder and one document per file — path, filename, media type, SHA-256, arrival time — and the add screen's *Queued* now describes rows rather than an intention.

Four things this ticket decided rather than assumed:

- **Recognition is global; the index is per source.** The user's problem is the same contract in three folders, and three folders are three sources — so `add()` looks the hash up across every live document. The partial unique index underneath is narrower on purpose — `uq_documents_live_source_id_sha256`, which the v1 migration already created and which no model declared, so an autogenerate run would have proposed dropping it. The application check produces the sentence; the index makes a second live row impossible when a later code path forgets to ask. Reasoning in `decisions.md`, 2026-08-28.
- **`queued` is a status, added to both vocabularies and made the default.** None of `indexing`, `ready`, `attention` or `deleted` was true of a row this ticket creates, and storing `indexing` is what a progress bar that never moves gets rendered from.
- **The server re-detects.** `api/src/askwell/filetypes.py` is a deliberate second copy of the browser's signature table, reading the file itself. Nothing the client says about a type reaches a row. One divergence is deliberate and recorded: the server will not take a `.md`/`.txt`/`.html` file away from the files route on a comma or a `CREATE` keyword. The client still will, which is an open item below.
- **The hash is over content and nothing else** — never the name, never the mtime. The file's identity (device, inode, size, mtime) is checked before and after the read, and a file that keeps changing is re-read up to three times and then reported rather than recorded with a hash of bytes nobody will read again.

Two requirements carried forward from earlier tickets are now met: **adding is a decisions record** (one for the source, one per document, each naming the path) and **a refusal reaches the operational log**. A duplicate and a refusal are *not* decisions records — nothing changed.

**Before that: `M1-ADD-ING-021`** — Askwell can be told which folders it may read. `0.2.2`.

Indexing in place means Askwell reads the user's own directories, so it needs a route to them that is narrow and explicit. That route is now two things that must not be confused:

- **The registry** — `roots`, its own table, tombstoned on removal. It is the *permission*: `askwell.roots.covering()` is the check, and a path no row covers is never read. It resolves symlinks, because one link inside a nominated folder would otherwise stand in for the whole disk.
- **The mount** — `ASKWELL_ROOTS_MOUNT`, one host directory bind-mounted read-only into the API and worker **at the same absolute path it has on the host**. It is the *route*. Identity mounting is deliberate: `sources.root_path` holds host paths, and any other mount point would need host↔container translation everywhere a path is stored, shown or reopened.

Mount state is **probed on every read and never stored**. A stored value reports an unplugged USB drive as available an hour later, and nothing would ever correct it.

Four unreadable states, kept apart because they have four different fixes: `not_mounted` (a line in `.env` and bring the stack up again), `unavailable` (a drive or share not connected — **never** rendered as deleted or as moved), `unreadable` (permissions, or SELinux on the mount), `available`.

A folder outside the window is **registered anyway**, reporting what to set and that the stack must come up again. Everything else unreadable is refused at registration, because it is true now and will not fix itself; a missing mount is not.

Reachable at `GET /roots`, `POST /roots`, `GET /roots/covering`, `GET /roots/{id}/removal`, `DELETE /roots/{id}`, and in the interface under Settings → Folders Askwell may read. Registering and removing are decisions records. Full reasoning in `decisions.md`, 2026-08-27; the flow is specified in `ux/add-source.md` §7, which is new — no screen covered path registration before.

**Before that: [#89](https://github.com/Rumeasiyan/askwell/issues/89)** — inference is three processes. This blocked M1 retrieval and is now cleared.

```
generation  ready   Qwen3.5-4B-Q4_K_M.gguf
embedding   ready   bge-m3-FP16.gguf              1024 dimensions
reranking   ready   bge-reranker-v2-m3-FP16.gguf
```

Through the client, from inside the API container, over one socket:

```
generate: 8 tokens
embed:    2 vectors of 1024 dimensions
rerank:   "how much notice to end the lease?"
  -2.419  Either party may terminate on ninety days written notice.
  -7.846  The tenant shall pay rent monthly in advance.
 -11.028  The premises shall be used for office purposes only.
```

The reranker puts the right passage first by a wide margin, which is the signal retrieval needs. **The scores are raw logits, not probabilities** — negative and unbounded — so only their order means anything, and the client returns them sorted rather than inviting a threshold on the number.

**Why this was necessary rather than tidy.** Embeddings from the generation model came back at 2560 dimensions where `chunks.embedding` is `vector(1024)`. They would not have been merely poor for retrieval — the database would have refused the insert. And `--reranking` needs its own model and is mutually exclusive with generation.

Each role is supervised independently: one model missing does not stop the others, because a user with no reranker can still ask questions and reporting the assistant down for it would be false. Three supervisors share one state file, written under a lock — without it they read-modify-write over each other and a role's entry vanishes, which the API would read as that role never having reported.

Both models verified against the registry before their names were written down (C9): `bge-m3` is MIT with 36M downloads, `bge-reranker-v2-m3` is Apache-2.0 with 18M. Both ungated.

## The build runner is live, and its first ticket

`M1-ADD-ING-021` was built by `scripts/build-runner.sh` end to end: gate proved on a clean tree, build, gate (**failed on lint**), one fix attempt with the failing output, gate again (passed), audit, manual-test document.

**The audit failed the work, and it was right to.** Four defects a passing gate cannot see. Two were serious:

- **A symlinked root broke the ticket's primary acceptance criterion.** `covering()` compared a file's *resolved* path against the root's *unresolved* one, so `/home/anna/work -> /mnt/big/work` registered happily and then covered nothing — and the refusal offered to nominate the same folder again. Fixed by resolving both sides, with a test for the shape and a second test proving a symlink *inside* a root still cannot escape.
- **`probe()` blocked the event loop.** A synchronous `os.scandir` reached from three request handlers, with no thread and no timeout. `AGENTS.md` §6 forbids exactly this, and the consequence is concrete: one hard-mounted share whose server has gone away would hang every request including `/health` — the surface that exists to say what is wrong would be the first thing to stop answering. Now off the loop with a 3s ceiling, and `listing` probes concurrently so one dead share costs the wait once rather than once per root ahead of it.

The other two: the network-share warning never fires in the ordinary first-run order, and there were no HTTP-level tests for any of the five endpoints. Eight now exist, including one for the route-ordering hazard the code warns about itself — `/roots/covering` must be declared before `/roots/{root_id}` or it becomes a 422 about a malformed UUID.

**Six runner bugs found by running it**, all mine: the gate was a stub returning success; the ledger was empty so it would have rebuilt M0; the agent call was never implemented; `run_agent` read `$4` under `set -u`; `guard_record_spend` was called with one argument of two; and the agent had no write permission, so its first working run produced a design document and zero files.
